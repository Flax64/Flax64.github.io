Organización del procesador

La organización del procesador se refiere a la forma en que los diferentes componentes internos de la Unidad Central de Procesamiento (CPU) están interconectados y cómo trabajan en conjunto para ejecutar las instrucciones de un programa.

Componentes Principales

Unidad Aritmética Lógica (ALU): Es el "cerebro" matemático y lógico del procesador. Realiza operaciones aritméticas (suma, resta, multiplicación, división) y operaciones lógicas (AND, OR, NOT, XOR) con los datos.
Unidad de Control (CU): Actúa como el director de orquesta del procesador. Interpreta las instrucciones de la memoria, genera señales de control para coordinar las acciones de los demás componentes (como la ALU, los registros y la memoria), y asegura que las instrucciones se ejecuten en la secuencia correcta.
Registros: Son pequeñas áreas de almacenamiento de alta velocidad dentro del procesador. Se utilizan para guardar temporalmente datos, direcciones de memoria o información de control que la CPU necesita acceder rápidamente durante la ejecución de las instrucciones. Los diferentes tipos de registros (que veremos en el siguiente punto) cumplen funciones específicas.
Caché: Es una memoria de alta velocidad más pequeña que la memoria principal (RAM) pero más rápida. Almacena copias de los datos e instrucciones que se utilizan con más frecuencia, lo que permite al procesador acceder a ellos más rápidamente y mejorar el rendimiento general del sistema. Hay varios niveles de caché (L1, L2, L3), con diferentes tamaños y velocidades.
Buses Internos: Son las vías de comunicación dentro del procesador que permiten la transferencia de datos, direcciones y señales de control entre los diferentes componentes.

Interconexión de Componentes

La forma en que estos componentes están interconectados es crucial para el funcionamiento del procesador. Generalmente, se utilizan buses para comunicar los datos, las direcciones de memoria y las señales de control.

Bus de Datos: Transporta los datos entre los diferentes componentes.
Bus de Direcciones: Especifica la ubicación de la memoria o del puerto de E/S al que se está accediendo.
Bus de Control: Lleva las señales de control desde la Unidad de Control a los otros componentes para coordinar sus acciones.

Estructura de registros

Los registros son una parte esencial de la arquitectura del procesador. Son pequeñas ubicaciones de almacenamiento de alta velocidad directamente accesibles por la ALU y la Unidad de Control. Su función principal es mantener temporalmente los datos y la información de control que el procesador necesita para ejecutar las instrucciones de manera eficiente.

La estructura de registros se puede categorizar principalmente en dos tipos.

Registros visibles para el usuario

Estos son los registros a los que los programadores pueden acceder directamente a través del lenguaje ensamblador (o indirectamente a través de lenguajes de alto nivel mediante el compilador). Se utilizan para una variedad de propósitos generales y específicos definidos por la arquitectura del conjunto de instrucciones (ISA) del procesador. Algunos ejemplos comunes incluyen:

  • Registros de Propósito General (GPRs): Se utilizan para almacenar operandos (datos de entrada y salida) de las operaciones aritméticas y lógicas. Los programadores tienen flexibilidad para utilizarlos según sus necesidades. La cantidad de GPRs varía significativamente entre diferentes arquitecturas de procesadores (por ejemplo, algunas arquitecturas pueden tener 8, 16, 32 o incluso más).
  • Registros de Datos: Algunos procesadores tienen registros específicamente designados para contener datos numéricos (enteros, coma flotante).
  • Registros de Direcciones: Se utilizan para almacenar direcciones de memoria. Esto incluye:
    • Puntero de Pila (Stack Pointer - SP): Mantiene la dirección de la cima de la pila, una estructura de datos utilizada para almacenar información temporal como direcciones de retorno de funciones y variables locales.
    • Puntero de Base (Base Pointer - BP) o Puntero de Marco (Frame Pointer - FP): Se utiliza para referenciar las variables locales dentro de un marco de pila de una función.
    • Registro Índice: Se utiliza en conjunto con una dirección base para calcular la dirección efectiva de un operando en la memoria (útil para acceder a elementos de arrays o tablas).
  • Registros de Segmento: En arquitecturas segmentadas (menos comunes en procesadores modernos de escritorio), estos registros almacenan las direcciones base de diferentes segmentos de memoria (código, datos, pila).

Registros de control y de estados

Estos registros son utilizados por la Unidad de Control para controlar el funcionamiento del procesador y almacenar información sobre el estado actual del sistema y los resultados de las operaciones. Generalmente no son directamente manipulados por los programas de usuario (aunque pueden ser accedidos indirectamente a través de llamadas al sistema). Algunos ejemplos importantes son:

  • Contador de Programa (Program Counter - PC) o Puntero de Instrucción (Instruction Pointer - IP): Contiene la dirección de la siguiente instrucción que se va a ejecutar. La Unidad de Control actualiza este registro después de que se busca una instrucción (fetch) o como resultado de una instrucción de salto o bifurcación.
  • Registro de Instrucción (Instruction Register - IR): Almacena temporalmente la instrucción que se acaba de buscar de la memoria y está siendo decodificada y ejecutada.
  • Registro de Estado (Status Register) o Registro de Banderas (Flags Register): Contiene bits individuales (flags) que indican el resultado de la última operación aritmética o lógica. Los flags comunes incluyen:
    • Bandera de Cero (Zero Flag - Z): Se activa si el resultado de la última operación fue cero.
    • Bandera de Signo (Sign Flag - S): Indica el signo del resultado de la última operación (generalmente el bit más significativo).
    • Bandera de Desbordamiento (Overflow Flag - O): Indica si hubo un desbordamiento aritmético (el resultado fue demasiado grande o demasiado pequeño para ser representado en el registro).
    • Bandera de Acarreo (Carry Flag - C): Indica si hubo un acarreo o préstamo en la última operación aritmética.
    • Bandera de Paridad (Parity Flag - P): Indica si el número de bits '1' en el resultado es par o impar.
  • Registro de Puntero de Interrupción: Almacena la dirección del vector de interrupciones, una tabla que contiene las direcciones de las rutinas de servicio de interrupciones.
  • Registros de Control de Memoria (por ejemplo, registros de la Unidad de Gestión de Memoria - MMU): Se utilizan para gestionar la memoria virtual, la protección de la memoria y la traducción de direcciones virtuales a físicas.

Ejemplos de registros de CPU reales

Arquitectura x86 (Intel/AMD)

  • Registros de Propósito General: EAX, EBX, ECX, EDX (de 32 bits), y sus extensiones de 64 bits RAX, RBX, RCX, RDX. También existen registros como ESI, EDI, ESP, EBP (y sus equivalentes de 64 bits) que tienen usos convencionales para indexación, puntero de pila y puntero de base.
  • Registro de Instrucción: Invisible directamente para el programador.
  • Contador de Programa: EIP (32 bits) y RIP (64 bits).
  • Registro de Estado: EFLAGS (32 bits) y RFLAGS (64 bits), que contienen las banderas de estado y control.
  • Registros de Segmento: CS, DS, SS, ES, FS, GS (aunque su uso es menos común en modo protegido de 64 bits).

El ciclo de instrucción

El ciclo de instrucción, también conocido como ciclo fetch-decode-execute, es el proceso fundamental mediante el cual la Unidad Central de Procesamiento (CPU) ejecuta las instrucciones de un programa almacenado en la memoria. Cada instrucción en un programa sigue este ciclo básico para ser procesada.

Ciclo Fetch-Decode-Execute

Este es el núcleo del ciclo de instrucción y consta de las siguientes etapas principales:

Fetch (Búsqueda)

  • La CPU busca la siguiente instrucción que debe ser ejecutada desde la memoria principal (RAM).
  • La dirección de la siguiente instrucción a buscar está contenida en el Contador de Programa (PC).
  • El valor del PC se envía a la memoria a través del bus de direcciones.
  • La memoria recupera la instrucción ubicada en esa dirección y la envía de vuelta a la CPU a través del bus de datos.
  • La instrucción se almacena temporalmente en el Registro de Instrucción (IR).
  • El Contador de Programa (PC) generalmente se incrementa en este punto para apuntar a la siguiente instrucción en secuencia.

Decode (Decodificación)

  • La Unidad de Control (CU) analiza la instrucción que se encuentra en el Registro de Instrucción (IR).
  • Durante la decodificación, la CU determina:
    • La operación que se debe realizar (por ejemplo, suma, resta, carga de datos).
    • Los operandos involucrados (los datos que se utilizarán en la operación). Estos operandos pueden estar en registros, en la memoria o ser valores inmediatos dentro de la propia instrucción.
    • El modo de direccionamiento utilizado para acceder a los operandos en la memoria (si es necesario).
  • La CU genera las señales de control necesarias para que los otros componentes de la CPU (como la ALU y los registros) realicen la operación especificada.

Execute (Ejecución)

  • La Unidad de Control dirige a la Unidad Aritmética Lógica (ALU) para que realice la operación especificada en la instrucción decodificada.
  • Si la instrucción implica una operación aritmética o lógica, la ALU toma los operandos necesarios de los registros o la memoria y realiza el cálculo.
  • Si la instrucción implica una transferencia de datos (por ejemplo, cargar datos de la memoria a un registro o almacenar datos de un registro en la memoria), se activan los buses y la unidad de memoria para realizar la transferencia.
  • Los resultados de la ejecución se almacenan generalmente en un registro o en la memoria.
  • El Registro de Estado (Flags Register) puede ser actualizado por la ALU para reflejar el resultado de la operación (por ejemplo, si el resultado fue cero, negativo, o si hubo un desbordamiento).
Después de la fase de ejecución, el ciclo se repite, comenzando con la búsqueda de la siguiente instrucción apuntada por el Contador de Programa (PC). Este ciclo continúa hasta que se ejecuta una instrucción de "alto" o hasta que se interrumpe el programa.

Segmentación de instrucciones (Instruction Pipelining)

La segmentación es una técnica para mejorar el rendimiento del procesador. En lugar de esperar a que una instrucción complete todo el ciclo Fetch-Decode-Execute antes de comenzar con la siguiente, la segmentación permite que múltiples instrucciones se encuentren en diferentes etapas del ciclo simultáneamente.
Imagina una línea de ensamblaje donde cada estación realiza una tarea específica. De manera similar, en un pipeline de instrucciones, la ejecución de una instrucción se divide en varias etapas secuenciales (por ejemplo, Fetch, Decode, Execute, Memory Access, Write Back). Mientras una instrucción está en la etapa de "Decode", la siguiente instrucción puede estar en la etapa de "Fetch", y la instrucción anterior puede estar en la etapa de "Execute".
Esto permite que se complete una instrucción por ciclo de reloj (idealmente), lo que aumenta significativamente el rendimiento general del procesador (throughput). Sin embargo, la segmentación introduce desafíos como los riesgos de datos (cuando una instrucción necesita un resultado que aún no ha sido calculado por una instrucción anterior en el pipeline) y los riesgos de control (cuando una instrucción de salto o bifurcación cambia el flujo de ejecución).

Conjunto de instrucciones (Instruction Set Architecture - ISA)

El conjunto de instrucciones (ISA) define todas las instrucciones que un procesador puede entender y ejecutar. Incluye:

Características

  • Tipos de instrucciones: Aritméticas, lógicas, de transferencia de datos (carga/almacenamiento), de control de flujo (saltos, bifurcaciones, llamadas a subrutinas), de entrada/salida, etc.
  • Formatos de instrucción: La estructura de una instrucción, incluyendo el código de operación (opcode) que especifica la operación a realizar y los campos para los operandos (registros, direcciones de memoria, valores inmediatos). Los formatos pueden variar en longitud y la forma en que especifican los operandos.
  • Tipos de datos soportados: Los formatos de los datos que el procesador puede manipular (enteros de diferentes tamaños, números de coma flotante, caracteres, etc.).
  • Modos de direccionamiento: Las diferentes formas en que se pueden especificar las direcciones de los operandos en la memoria (lo veremos en el siguiente punto).
  • Número de operandos por instrucción: Algunas arquitecturas tienen instrucciones de cero, uno, dos o tres operandos.

Funciones

  • Permite a los programadores escribir programas que el procesador pueda ejecutar.
  • Actúa como una interfaz entre el software y el hardware.
  • Influye directamente en el diseño del procesador y su rendimiento.
  • Diferentes arquitecturas de procesadores (por ejemplo, x86, ARM, RISC-V) tienen diferentes ISAs.

Modos de direccionamiento

Los modos de direccionamiento definen cómo se especifica la ubicación de un operando (un dato) dentro de una instrucción. Diferentes modos ofrecen flexibilidad para acceder a los datos de diversas maneras. Algunos modos de direccionamiento comunes incluyen:

  • Inmediato: El operando es un valor constante que está incluido directamente en la instrucción.
  • Registro: El operando está ubicado en uno de los registros del procesador.
  • Directo (Absoluto): La instrucción contiene la dirección de memoria exacta donde se encuentra el operando.
  • Indirecto: La instrucción contiene la dirección de memoria donde se encuentra la dirección del operando.
  • Registro Indirecto: La instrucción especifica un registro que contiene la dirección de memoria del operando.
  • Desplazamiento (o Base + Desplazamiento): La dirección del operando se calcula sumando un valor de desplazamiento (constante en la instrucción) al contenido de un registro base.
  • Indexado: La dirección del operando se calcula sumando el contenido de un registro índice a una dirección base (que puede estar en otro registro o en la instrucción). Puede incluir un factor de escala para acceder fácilmente a elementos de arrays.
  • Relativo al PC: La dirección del operando se calcula sumando un desplazamiento al valor actual del Contador de Programa (útil para saltos y bifurcaciones dentro del mismo segmento de código).

Casos de estudio

Analizar casos de estudio de CPUs reales es una excelente manera de consolidar los conceptos que hemos visto sobre la organización, la estructura de registros y el ciclo de instrucción. Cada arquitectura de CPU tiene sus propias características y optimizaciones, influenciadas por su diseño, el mercado al que se dirige y la época en la que fue desarrollada.

Intel x86 (por ejemplo, Intel Core i7/i9)

  • Organización:
    • Arquitectura compleja (CISC - Complex Instruction Set Computer) que ha evolucionado a lo largo de décadas.
    • Utiliza una microarquitectura segmentada y superescalar para lograr un alto rendimiento.
    • Incluye múltiples unidades de ejecución, predicción de saltos avanzada y una compleja jerarquía de caché (L1, L2, L3).
    • Implementa técnicas de ejecución fuera de orden (out-of-order execution) para optimizar el uso de las unidades de ejecución.
  • Estructura de Registros:
    • Un conjunto de registros de propósito general (RAX, RBX, RCX, RDX, RSI, RDI, RSP, RBP, R8-R15) de 64 bits.
    • Registros de segmento (CS, DS, SS, ES, FS, GS), aunque su uso directo es limitado en modo de 64 bits.
    • Un registro de estado (RFLAGS) que contiene banderas de condición y control.
    • Un puntero de instrucción (RIP).
    • Registros para operaciones de coma flotante (XMM, YMM, ZMM).
    • Registros de control del sistema (CR0-CR4, y más en sistemas de 64 bits) para gestionar la memoria y otros aspectos del sistema.
  • Ciclo de Instrucción:
    • El ciclo básico Fetch-Decode-Execute se implementa a través de un pipeline complejo con muchas etapas para permitir la ejecución simultánea de múltiples instrucciones.
    • La decodificación de las instrucciones CISC puede ser compleja, a menudo dividiéndose en microoperaciones (uops) que luego se ejecutan en el pipeline.
    • Soporta una amplia variedad de modos de direccionamiento.

ARM (por ejemplo, ARM Cortex-A72, Apple M1/M2)

  • Organización:
    • Arquitectura RISC (Reduced Instruction Set Computer) diseñada para eficiencia energética y rendimiento.
    • Microarquitecturas segmentadas y superescalares modernas.
    • Énfasis en la ejecución eficiente con un menor número de ciclos por instrucción en comparación con CISC.
    • Utiliza también jerarquías de caché.
  • Estructura de Registros:
    • Un conjunto más grande de registros de propósito general (por ejemplo, 31 registros de 64 bits en la arquitectura AArch64).
    • Un contador de programa (PC).
    • Un puntero de pila (SP).
    • Un registro de enlace (LR) para almacenar la dirección de retorno de las funciones.
    • Un registro de estado (CPSR o SPSR).
    • Registros para operaciones SIMD (NEON).
  • Ciclo de Instrucción:
    • El ciclo Fetch-Decode-Execute se implementa con un pipeline más sencillo en comparación con x86, aunque las microarquitecturas de alto rendimiento de ARM también utilizan pipelines profundos.
    • Las instrucciones RISC son generalmente de longitud fija y más fáciles de decodificar.
    • Soporta varios modos de direccionamiento, aunque generalmente menos complejos que en x86.

RISC-V

  • Organización:
    • Una arquitectura RISC abierta y modular, diseñada para ser extensible y adaptable a diferentes necesidades.
    • Implementaciones pueden variar ampliamente en complejidad, desde núcleos muy simples para sistemas embebidos hasta procesadores de alto rendimiento.
    • Soporta diferentes extensiones para características como aritmética de coma flotante, instrucciones atómicas y procesamiento vectorial.
  • Estructura de Registros:
    • Generalmente incluye 32 registros de propósito general (x0-x31). El registro x0 está cableado a cero.
    • Un contador de programa (PC).
    • Un registro de estado (CSR - Control and Status Registers) para gestionar el estado del procesador y las funciones privilegiadas.
    • Registros de coma flotante (f0-f31) si la extensión de coma flotante está presente.
  • Ciclo de Instrucción:
    • Sigue el ciclo Fetch-Decode-Execute con un pipeline que puede variar en profundidad según la implementación.
    • Las instrucciones RISC-V son de longitud fija (generalmente 32 bits) y tienen un formato simple, lo que facilita la decodificación.
    • Ofrece un conjunto de modos de direccionamiento básicos y bien definidos.
